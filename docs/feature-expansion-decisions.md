# 機能拡張と次段階の判断

HiFiScoutは「正しく探せる → 個体の条件を比べられる → 欲しい出物を待てる → 購入を判断できる」という流れを支えます。機能の実装、データの充足、本番への反映を分けて扱います。PRのマージだけでデータの確認や本番反映まで完了したとは判断しません。

## 現在の機能を育てる

| 目的 | 利用できる基盤 | 継続して確認すること |
| --- | --- | --- |
| 個体の条件を選ぶ | 出品ごとの状態・付属品・保証・販売単位、同一出品でのAND検索、管理者訂正、再開可能な再抽出 | 記載なしと明示的な「なし」の区別、ショップ・項目ごとの充足率、訂正の保持 |
| 候補機種を比較する | 製品比較URL、出典付き仕様、確認済みの前後継機種・シリーズ | 出典の有効性、機種と仕上げの区別、確認期限を過ぎた関係の再確認 |
| 継続して探す | 名前付き保存検索、Atom、希望価格・検討メモ、再訪時の変化表示 | 保存・再利用・訂正の操作が完了できるか、取得失敗時に記録を失わないか |
| 設置・接続条件で探す | カテゴリ別の機能・仕様と、寸法・重量・入出力系統数の検索 | カテゴリごとの仕様充足率、単位、端子の左右1組と系統数の区別 |
| 価格を判断する | 既存価格指標、状態・販売単位別価格帯、月次の掲載価格・初回観測・終了の集計 | 独立した出品数・店舗数・期間、少数区分、履歴の偏り、集計保留の範囲 |

実装と保存上限の正本は[データ基盤](./data-platform-architecture.md)、HTTP契約、各機能のソースです。出典付き仕様や機種関係は管理者の確認・登録が必要です。過去のショップ本文を追加取得して自動的に埋めません。相場の初期集計は既存メンテナンスで順次進み、既存出品の状態再抽出は管理画面の再開可能な処理を利用します。

## 次の拡張に進む前の確認

判断のたびに対象カテゴリ・観測期間・独立した対象数・不足情報を記録します。下記は評価手順であり、利用率や費用削減が既に実証されたという意味ではありません。

| 軸 | 評価すること | 証拠の取り方 |
| --- | --- | --- |
| 利用価値 | 条件設定から候補比較、店舗ページへの到達まで完了するか。保存検索・希望価格・メモが再訪時にも役立つか | 操作確認と利用者フィードバック。購入を観測できない間、店舗への遷移は購入実績と区別する |
| データ品質 | 状態・仕様の充足率、誤分類・誤統合、古い在庫、訂正の再発が改善するか | 管理画面のカバレッジ、誤情報報告、確認済みカタログ。項目単位の評価は既存エクスポートを使い、公開検索に全件集計を追加しない |
| 運用負荷 | D1の読込・書込・文数、CPU、処理待ちが許容範囲に収まるか | 実D1のCI予算テストと、本番の既存メトリクス・処理ログを分けて確認。CIの件数上限を本番CPUの保証とはみなさない |

端末内の検索名・メモ・希望価格・お気に入り履歴を、利用状況の把握のために自動送信しません。利用計測を導入する場合は、必要なイベントと保存期間を別途設計します。現時点のコードだけから利用率を推定しません。

## 条件付きの拡張

| 拡張 | 着手判断に必要な情報 | 着手時の小さな実装単位 |
| --- | --- | --- |
| マイシステム | 所有機器と購入候補を分ける需要、必要な仕様項目、接続条件の充足率 | まず端末内の所有機器・メモ管理。接続可否は必要な端子・電圧等が確認できる場合だけ扱う |
| メール・Web Push | Atomと再訪確認で足りない用途、希望頻度、配信費用と停止操作 | 通知先の確認・解除、収集完了後の変更イベント、重複抑制を分けて実装。現在の巡回頻度・夜間停止を前提にし、通知のために巡回を増やさない |
| 端末間同期 | 同期したい情報と競合時の期待、認証・削除・保持期間、運用費用 | 認証、データ同期、競合解決、端末内既存データの移行を別PRにする。privateなメモを共有URLへ載せない |
| 収集先拡大 | 既存店舗で不足するカテゴリ・メーカー、新店舗の利用条件・取得負荷・在庫精度 | [ショップ追加手順](./adding-shops.md)に従い、店舗単位で実装・計測・反映する |

これらは利用実績と運用条件を確認してから導入を決める対象です。現在のロードマップ対応だけでアカウント、配信基盤、新しい巡回先を追加する扱いにはしません。

## 反映と完了の記録

機能ごとのPRで検証・レビューを行い、mainへマージします。実デプロイは `deployment-identity` と同じSHAのE2E・管理画面・運用確認で追跡します。割当上限による延期や、既に反映済みのため変更がないケースは成功表示だけで新規反映と数えません。

受け入れ条件と実装PRの一覧は [#346](https://github.com/apaapapapapa/HiFiScout/issues/346)、[#344](https://github.com/apaapapapapa/HiFiScout/issues/344)、[ロードマップ #347](https://github.com/apaapapapapa/HiFiScout/issues/347)で管理します。条件付きの拡張や集計上限を超える製品への対応は、既存機能の完了と分けて追跡します。
